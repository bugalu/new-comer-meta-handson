セットアップ & スマホ実機確認

事前準備

前提: PC に git と Python 3（または Node.js）がインストールされていること。PCとスマホが同じWi-Fiネットワークに接続されていること。

手順

  1. リポジトリをクローンする

    git clone https://github.com/bugalu/new-comer-meta-handson.git
cd new-comer-meta-handson

  2. ローカルサーバーを起動する

    以下のどちらかを実行してください。

    python3 -m http.server 8080
    npx serve -l 8080

    「Serving HTTP on 0.0.0.0 port 8080 ...」のようなメッセージが出ればOKです。

  3. PCのローカルIPアドレスを確認する

    ipconfig getifaddr en0

    例: 192.168.1.10 のような数字が表示されます。

    ipconfig

    「IPv4 アドレス」の欄に表示される 192.168.x.x をメモしてください。

  4. PCのブラウザで確認する

    まず以下のURLにアクセスして、ページが表示されることを確認してください。

    http://localhost:8080

  5. スマホのブラウザでアクセスする

    手順3で確認したIPアドレスを使って、スマホのブラウザで以下のようなURLにアクセスします。

    http://あなたのIPアドレス:8080

    例: http://192.168.1.10:8080

    つながらない場合は:
    ・PCとスマホが同じWi-Fiに接続されているか確認
    ・ファイアウォールで8080番ポートがブロックされていないか確認
    ・macOS: 「システム設定 → ネットワーク → ファイアウォール」を確認
    ・Windows: 「Windows セキュリティ → ファイアウォール」を確認

スマホで確認できること

確認項目 操作
theme-color の反映 アドレスバーの色が青色になるか（Android Chrome）
telephone=no の効果 電話番号がリンク化されていないか
viewport の効果 ページが画面幅に最適化されて表示されるか
ホーム画面アイコン 「ホーム画面に追加」した時のアイコン・アプリ名
OGP表示 URLをLINEやSNSに貼った時のカード表示（※ローカルでは確認不可・本番公開後に確認）

title / description / OGP

<title> タグの役割

ブラウザのタブ、ブックマーク、検索結果のタイトルに表示されます。SEOの最重要要素のひとつです。

<title>metaタグ & スマホ制御 ハンズオン研修</title>
実際の表示

このページのブラウザタブを見てみましょう。タイトルが表示されているはずです。

<meta name="description"> の役割

検索結果のタイトル下に表示されるスニペット文です。120文字程度が目安。ユーザーのクリック率に直結します。

<meta name="description" content="metaタグの基本からOGP設定、ファビコン、 viewport、スマホブラウザ固有の制御まで 学べるハンズオン研修サイトです。">

OGP（Open Graph Protocol）とは

SNS（Twitter、Facebook、LINEなど）でURLをシェアした時に、タイトル・説明・画像をリッチに表示するための仕組みです。 

<!-- 基本のOGPタグ -->
<meta property="og:title" content="ページタイトル">
<meta property="og:description" content="説明文">
<meta property="og:type" content="website">
<meta property="og:url" content="https://example.com/">
<meta property="og:image" content="https://example.com/ogp.png">

<!-- Twitter用 -->
<meta name="twitter:card" content="summary_large_image">

OGP画像の基本

推奨サイズは 1200 x 630px（横長 1.91:1）。このサイズならほぼ全てのSNSで最適に表示されます。

例：https://x.com/Locoty_aomori/status/2056573923177959802

SNS 推奨サイズ カード種類
Twitter / X 1200 x 630px summary_large_image
Facebook 1200 x 630px （自動）
LINE 1200 x 630px （自動）
ポイント: OGP画像は絶対URLで指定する必要があります。相対パスではSNSクローラーが取得できません。

設定箇所と反映先

タグ 反映先
<title> ブラウザタブ / 検索結果 / ブックマーク
description 検索結果のスニペット
og:title SNSシェア時のタイトル
og:description SNSシェア時の説明文
og:image SNSシェア時のサムネイル画像
twitter:card Twitter/Xでのカード表示形式
見てみよう: ハコレコWebサイトをブラウザのDevToolで確認してみましょう。（タイトル、description、OGPタグ等がどのように書かれているか）

ファビコン / スマホHOME画面アイコン

favicon の役割

ブラウザタブ、ブックマーク一覧、履歴に表示される小さなアイコンです。サイトの視認性とブランド認知に直結します。 

            <!-- 従来のICO形式 -->
            <link rel="icon" href="/favicon.ico"
            sizes="48x48">

            <!-- SVG形式（モダンブラウザ向け・拡大に強い） -->
            <link rel="icon" href="/favicon.svg"
            type="image/svg+xml">
実際の表示

ブラウザタブの左端に小さなアイコンが表示されます（このサイトにはまだfavicon画像を設置していないのでデフォルトアイコンが表示されます）。

スマホHOME追加時のアイコン

iPhoneで「ホーム画面に追加」した時に表示されるアイコンです。

            <!-- iOS向け: 180x180px が推奨 -->
            <link rel="apple-touch-icon"
            sizes="180x180"
            href="/apple-touch-icon.png">

            <!-- Android向け: Web App Manifest -->
            <link rel="manifest" href="/site.webmanifest">

サイズ一覧

種類 サイズ 用途
favicon.ico 16x16, 32x32, 48x48 ブラウザタブ
favicon.svg 可変 モダンブラウザ（高解像度対応）
apple-touch-icon 180x180 iOSホーム画面
Android icon 192x192, 512x512 Androidホーム画面・スプラッシュ
Tips: 最低限 favicon.ico（48x48）と apple-touch-icon.png（180x180）を用意すれば大体カバーできます。

robots の設定

robots meta タグの役割

検索エンジンのクローラー（GoogleやBingのbot）に対して、そのページを検索結果に載せて良いか、リンク先を辿って良いかを伝えるためのメタタグです。

<meta name="robots" content="index, follow">

上記は「インデックスしてよい・リンクをたどってよい」という意味で、これがデフォルト挙動です（タグ自体を書かなくても同じ）。

index / noindex

そのページを検索結果に表示してよいかを制御します。

値 意味
index 検索結果に表示してよい（デフォルト）
noindex 検索結果に表示しないでほしい
<!-- 検索結果に出したくないページ --> <meta name="robots" content="noindex">
noindex を使うケース: 会員限定ページ、サンクスページ、検索結果ページ、重複コンテンツ、テスト・ステージング環境など、検索から見つけてほしくないページに設定します。

nofollow

そのページ内のリンクをクローラーに辿らせるかどうかを制御します。

値 意味
follow ページ内のリンクをたどってよい（デフォルト）
nofollow ページ内のリンクをたどらないでほしい 
            <!-- インデックスはOK、リンクはたどらせない -->
            <meta name="robots" content="index, nofollow">

            <!-- 両方拒否（最も厳しい設定） -->
            <meta name="robots" content="noindex, nofollow">

個別のリンク単位で制御したい場合は、<a> タグに rel="nofollow" を指定します（ユーザー投稿のURLなど、信頼できないリンクに使われます）。

検索エンジンとの関係

robots meta タグはクローラーへのお願いです。Google・Bing・Yahoo!などの主要な検索エンジンはこれに従いますが、悪意のあるbotは無視することもあります。

仕組み 役割
robots.txt サイト全体のクロール可否を制御（ファイル単位）
<meta name="robots"> ページ単位でインデックス・リンク追跡を制御
X-Robots-Tag ヘッダ HTTPレスポンスヘッダで制御（PDF等のHTML以外にも使える）
rel="nofollow" 個別リンク単位での制御
重要: noindex は「インデックスしないで」というリクエストです。すでにインデックスされているページに後から noindex を付けても、クローラーが再訪して認識するまでは検索結果に残ります。

開発環境・ステージング環境での扱い

開発中のサイトやステージング環境が誤って検索結果に出ると、本番サイトと内容が重複してSEO上のペナルティを受けたり、未公開情報が漏れたりするリスクがあります。 

            <!-- ステージング・開発環境では必ず設定する -->
            <meta name="robots" content="noindex, nofollow">

環境変数や設定ファイルで本番か否かを判定し、本番以外は noindex, nofollow を出力する実装にしておくのが定石です。

本番反映時の事故: 開発環境用に書いた noindex をそのまま本番にデプロイしてしまい、検索結果からサイトが消えるという事故は新人がやりがちな失敗のひとつです。リリース前のチェック項目に必ず入れましょう。

ブラウザ・スマホ固有の制御

telephone=no（電話番号の自動リンク化を無効にする）

スマホブラウザは数字の羅列を電話番号と誤認識し、自動的にリンク化することがあります。意図しないリンクを防ぐために設定します。

<meta name="format-detection" content="telephone=no">
デモ: この数字はどう表示される？

03-1234-5678

このページでは telephone=no を設定済みなので、上の数字はリンクにならないはずです。

設定しなかった場合、iOSのSafariなどでは自動的に電話リンクになります。

theme-color（テーマカラー）

Android Chromeのアドレスバー周辺の色や、Safari 15+のタブバーの色を変更できます。

<meta name="theme-color" content="#2563eb">
デモ

このサイトには #2563eb（青色）が設定されています。Android Chromeで閲覧するとアドレスバーが青くなります。

apple-touch関連の設定

iOSでWebサイトをホーム画面に追加した際の挙動を制御します。

              <!-- フルスクリーン表示を有効にする -->
              <meta name="apple-mobile-web-app-capable"
              content="yes">
              <!-- ステータスバーの外観 -->
              <meta name="apple-mobile-web-app-status-bar-style"
              content="default">
              <!-- ホーム画面に表示されるアプリ名 -->
              <meta name="apple-mobile-web-app-title"
              content="meta研修">
status-bar-style 効果
default 白い背景のステータスバー
black 黒い背景のステータスバー
black-translucent 半透明（コンテンツがステータスバー裏に回り込む）

metaタグで制御できる範囲

制御内容 metaタグ 対象ブラウザ
電話番号の自動リンク format-detection iOS Safari
アドレスバーの色 theme-color Android Chrome / Safari 15+
フルスクリーンモード apple-mobile-web-app-capable iOS Safari
ステータスバー外観 apple-mobile-web-app-status-bar-style iOS Safari
ホーム画面アプリ名 apple-mobile-web-app-title iOS Safari
表示領域の制御 viewport 全ブラウザ
注意: metaタグで制御できるのはブラウザの表示・挙動の一部のみです。ブラウザのセキュリティ設定やOS全体の制御はできません。

viewport の設定

viewport の役割

スマホブラウザの「仮想的な画面幅」を制御するメタタグです。これがないと、スマホでもPC向けの幅（通常980px）でページが描画されて、文字が極端に小さく表示されてしまいます。

<meta name="viewport" content="width=device-width, initial-scale=1.0">

width=device-width

ページの幅をデバイスの画面幅に合わせます。iPhone SE なら 375px、iPad なら 768px、といった具合にデバイスごとの最適な幅になります。

デバイス例 device-width
iPhone SE 375px
iPhone 14 390px
iPhone 14 Pro Max 430px
iPad 768px
iPad Pro 12.9" 1024px

initial-scale

ページ読み込み時の初期ズーム倍率です。1.0 は等倍（ズームなし）です。

プロパティ 値 説明
width device-width デバイスの幅に合わせる
initial-scale 1.0 初期ズーム倍率
minimum-scale 1.0 最小ズーム倍率
maximum-scale 5.0 最大ズーム倍率
user-scalable yes / no ピンチズームの可否
アクセシビリティ注意: user-scalable=no や maximum-scale=1.0 はユーザーのズームを無効にしてしまうため、アクセシビリティガイドラインに反します。特別な理由がない限り使わないでください。

レスポンシブデザインとの関係

viewportの設定はレスポンシブデザインの前提条件です。CSSのメディアクエリは viewport の幅に基づいて動作します。 

              /* viewport が設定されていて初めて、
                以下のメディアクエリが期待どおり動く */
              @media (max-width: 768px) { .sidebar {
              display: none; } }
              @media (max-width: 480px) { .header h1 {
              font-size: 1.25rem; } }

viewport 未設定時の挙動

viewport を設定しないと以下のような問題が起きます:

問題 原因
文字がとても小さい 980px幅をスマホ画面に縮小するため
横スクロールが発生 PC幅前提のレイアウトがはみ出す
メディアクエリが効かない ブラウザが980px幅と認識するため
タップしづらい ボタンやリンクが極端に小さくなる
実験してみよう

ブラウザの開発者ツールで、この <head> 内の viewport メタタグを削除してリロードしてみましょう。表示がどう変わるか確認できます。
